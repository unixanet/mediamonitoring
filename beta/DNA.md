# DNA проекта

Единый источник правды: инфраструктура, доступы, решения. Обновлять при каждом изменении (добавлять, править, удалять устаревшее).

## Цель
Вместо 4 разных WordPress-источников: краулер тянет до 150 RSS в одну БД, Manticore индексирует эту БД, на нём строятся алерты и рассылка ключевых слов клиентам. Прирост: до 700 000 статей в год. Подробности и план: [README.md](../README.md).

## Админка (beta)
- Домен: `beta.mediamonitoring.am` (после апгрейда это админка проекта).
- Функции (по мере добавления): пользователи (добавить/удалить), источники (список, добавить, удалить), нагрузка БД и краулера.
- Стек: чистый PHP 8.1+ (без фреймворка) + MySQL + Tailwind (CDN). Код в `beta/`, document root = `beta/`.
- Вход: `/login.php` (CSRF, bcrypt, лимит 5 неудачных попыток с IP за 15 мин). Стартовый пользователь: `admin` / `Beta#2026Admin` (роль owner).
- Дизайн (утверждён 2026-11-02, вариант A «Fluent»): светлый корпоративный интерфейс, левое меню 248px, верхняя панель с поиском и статусом краулера, карточки с тонкой голубой рамкой, нижняя панель навигации на телефоне. Токены в `lib/layout.php` (Tailwind config) и `ui()` в `lib/helpers.php`. Макеты: артефакт «Media Monitoring Admin: chosen design A». (Старое описание ниже устарело.)
- Прежнее описание: тонкие чёрные рамки, скруглённые углы, мягкие тени, тонкие линии между строками списков. Палитра только: белый, чёрный, голубой `#0078D4` (белый текст на голубом). Оранжевый и серый текст не используются. Все классы стилей централизованы в `ui()` (`lib/helpers.php`).
- Язык интерфейса: английский. i18n: `t('English text')`, переводы в `lang/<код>.php` (`ru`, `hy` добавим позже).
- Меню: группы сворачиваются кнопкой +/− (состояние хранится в localStorage, группа с активной страницей открыта). (`nav_tree()` в `lib/layout.php`): Dashboard; Sources → All sources, Categories, Add source; Search; Users. Профиль: клик по пользователю внизу меню (`/profile.php`). Поиск также в верхней панели на каждой странице.
- Во всех списках сортировка по клику на заголовок колонки (на мобильном чипы Sort), пагинация по 50.
- Две БД-подключения: `db()` (админка) и `cdb()` (краулер). Время в БД везде UTC, в интерфейсе Asia/Yerevan.

## Роли и права (`PERMS` в `lib/helpers.php`)
- `admin`: всё (источники, категории, статьи, пользователи, профиль).
- `editor`: Dashboard, добавить источник, поиск, смена только своего пароля.
- Роль и активность пользователя перепроверяются из БД на каждый запрос. Нельзя удалить себя и последнего активного админа.

## Модуль Sources
- Список (admin): имя, тип, URL, категория, число статей, последняя статья, последняя проверка, статус. Действия: Articles, Edit, Fetch now (опросить сразу, ставит `next_check_at = NOW()`) / Start (для остановленного: включить и опросить сразу), Pause, Delete с выбором: «только источник» (статьи остаются в БД, в списках подписаны «(deleted source)») или «источник + все его статьи, логи и очередь» (пачками по 2000).
- Поля источника: имя, тип (rss / sitemap / telegram / facebook), URL, категория, какие статьи качать (всё / только новые / с даты), интервал опроса (1/2/3/5/10/15 мин; опция «авто» подстраивает под частоту публикаций, не быстрее заданного и не медленнее 15 мин), часовой пояс дат ленты (по умолчанию Yerevan, нужен только когда в дате нет зоны), открывать ли страницы статей, заголовки запросов (browser/bot), способ дедупа, active. Фото не храним, только текст и дата.
- Дедуп: способ `dedup_by` задаёт, из чего краулер считает `dedup_hash` (нормализованный URL, GUID, заголовок, заголовок+день, текст). Всегда включён, `UNIQUE (source_id, dedup_hash)`. Одна статья у разных источников допустима.
- `sources.extra` (JSON) зарезервирован под будущие доп. поля.
- Счётчики `articles_count`, `last_article_at` денормализованы в `sources`, их обновляет краулер.
- Удаление источника пока не чистит Manticore: когда подключим индекс, добавить удаление из индекса.

## Модуль Categories
- Таблица `categories`, у источника одна категория (`sources.category_id`). Список (admin): переименование, удаление (источники становятся без категории), создание. Новую категорию можно создать и из формы источника (admin).
- Клик по категории → `/articles.php?category=ID`: статьи всех её источников, сортировка по дате/названию/источнику. Так же `/articles.php?source=ID` для одного источника.

## Поиск
- `/search.php`: подстрока (`LIKE '%слово%'`) по заголовку и тексту либо только по заголовку, фильтр по категории, сортировка, сниппет с подсветкой, от 2 символов. Работает по статьям текущего года.
- Это временная реализация; когда подключим Manticore, заменим только запрос, интерфейс останется.

## БД краулера: `crawler` (`002crawler.sql`)
- `sources`, `categories`, `articles` (статьи текущего года; статусы полного текста), `article_raw` (сырой RSS gzip). Без FULLTEXT; поиск делает Manticore.
- Объём: до 700 000 статей в год. Индексы: `(source_id, dedup_hash)` unique, `(source_id, published_at)`, `(published_at)`.
- ID статей сквозные и не повторяются между годами (при архивации выставляем AUTO_INCREMENT новой таблицы).

## Годовая архивация
В конце года на одном сервере MySQL, атомарно:
1. `RENAME TABLE crawler.articles TO crawler_archive.articles_ГГГГ, crawler.article_raw TO crawler_archive.article_raw_ГГГГ;`
2. `CREATE TABLE crawler.articles LIKE crawler_archive.articles_ГГГГ;` и то же для `article_raw`.
3. `ALTER TABLE crawler.articles AUTO_INCREMENT = <последний id + 1>;`
Архивную БД `crawler_archive` можно потом дампом вынести на другой сервер. Счётчики в `sources` не обнуляются. Скрипт архивации напишем отдельно.

## Оригинальная ссылка статьи: где хранится (важно)
- БД `crawler`, таблица `articles`, колонка **`url`** (VARCHAR 2048, NOT NULL). Это оригинальная ссылка на статью на сайте источника. Берётся с самой страницы (`<link rel=canonical>` того же сайта), а если его нет, то конечный адрес после перенаправлений. Для отчётов, алертов и кнопки «Open original» использовать именно `articles.url`.
- Колонка **`feed_link`** (VARCHAR 2048, NULL): ссылка так, как её отдал источник (лента, карта сайта, список страниц), записывается только если она отличается от `url` (редирект, трекинговые параметры). Для аудита.
- Для Telegram `url` = ссылка на пост (`https://t.me/<канал>/<номер>`).
- Статья с неполным текстом (`partial`, `title_only`) тоже хранит `url`, по нему страница открывается повторно. Дедуп внутри источника идёт по `dedup_hash` (`UNIQUE(source_id, dedup_hash)`), по умолчанию режим `url`.
- Очередь `url_queue.url`: адреса, найденные в сайтмэпе или списке страниц, до скачивания. После скачивания в `articles` попадает `url` оригинала.
- При удалении источника «только источник» статьи остаются вместе с `url`; «источник и статьи» удаляет и их.
- План: индексатор Manticore читает журнал `article_changes` и берёт `articles.url` как атрибут документа (пока не реализовано).
- Если у источника страницы на нескольких языках (news.am `/hy/` и `/ru/`), каждая языковая версия сохраняется отдельной статьёй со своим `url`. Отфильтровать лишнюю можно в настройках источника: «Skip URLs containing» (`/ru/`).

## Движок (Python, папка `engine/`, сервис `mmengine`)
- Всё скачивание делает **Python-движок** (asyncio): `python3 -m engine run`. PHP только показывает данные и дергает локальный API `127.0.0.1:8765` (`lib/engineapi.php`: `engine_call`). Конфиг: `engine/config.json` (доступ к БД `crawler`, порт API, браузер).
- Способы: `rss` (RSS/Atom, feedparser), `sitemap` (robots.txt, индекс, новостные карты с заголовками), `listing` (список статей на странице: контейнер и шаблон ссылки определяются автоматически), `telegram` (`t.me/s/<канал>`, история), `facebook` (только через адрес ленты). YouTube не храним.
- Запрос: `auto` (сначала curl_cffi с отпечатком Chrome, при блокировке 403/429/444/503/Cloudflare на 6 часов переходит на настоящий браузер Playwright под Xvfb), `http`, `browser`; свой прокси на источник; профиль `browser` или честный `bot`.
- **Оригинальная ссылка**: `articles.url` = канонический адрес статьи (или конечный после редиректов), `articles.feed_link` = ссылка, как её отдал источник, если отличается. Сохраняется при скачивании, показывается в списках и на странице статьи («Open original»).
- **Главное правило: качаем статью целиком** (trafilatura + свои селекторы). `content_status`: `full`, `pending` (повторы 2м/10м/1ч/6ч/24ч, до 5 попыток), `partial`, `title_only` (сохранён заголовок и описание из ленты или карты сайта). Причина в `fail_reason`.
- robots.txt соблюдается (RFC 9309, кэш в `robots_cache`, переключатель на источник). Вежливость: страницы 1 запрос/с на хост, ленты 4/с.
- Дедуп на источник `UNIQUE(source_id, dedup_hash)` (url/guid/title/title_date/content). Правки статьи отслеживаются 3 дня; `article_changes` журнал для Manticore (upsert/delete).
- API: `GET /health`, `POST /detect` (превью способа до сохранения), `POST /source/{id}/fetch|retry`, `POST /article/{id}/retry`, `POST /extract-test`.
- Сервис: `ops/mmengine.service` (xvfb-run python3 -m engine run). Проверка: `python3 -m engine check`, проверка сайта: `python3 -m engine detect <адрес> [auto|http|browser]`.
- Установка зависимостей: `sudo apt-get install -y python3-pip python3-dev libxml2-dev libxslt1-dev xvfb` и `sudo pip3 install -r engine/requirements.txt`, `sudo PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers python3 -m playwright install --with-deps chromium`, `sudo mkdir -p /var/lib/mmengine`.
- Источник: «какие статьи» = всё в потоке / только новые с момента сохранения / с даты (только дата, без времени).

## Здоровье движка (`/health.php`, меню Engine)
Статей в час и график за 24 ч, источники «созревшие» и самая большая просрочка, очереди (ждут полный текст, sitemap-ссылки, неудачные), процессы (poller и воркеры, пульс), нагрузка CPU/память/диск, активные запросы БД, самые медленные и «молчащие» источники, самые большие таблицы.

## «Молчащие» источники
Раз в 10 минут считается частота публикаций за 7 дней (`sources.articles_7d`). Если ждём статью дольше max(6 × обычная пауза, 3 ч), ставится `silent_since`, в Logs событие `silent_source`, плашка Silent в списке и на странице источника; при появлении статей `source_recovered`.

## Журнал изменений для Manticore (`article_changes`)
Запись `upsert` пишется, когда статья готова к индексации: сразу (если полный текст пришёл с лентой), после дозагрузки полного текста, после правки (до 3 дней после публикации; `revision`, `updated_at`), после отказа от дозагрузки, а также если статья ждёт полный текст дольше 10 минут (уходит как есть). `delete` пишется при удалении источника вместе с данными. Manticore читает по `id > последний обработанный`; журнал хранится 30 дней. Сам читатель журнала ещё не написан.

## Эксплуатация
- Бэкапы: `ops/backup.sh` (cron ежедневно в 03:30, хранение 14 дней в `/var/backups/mediamonitoring`; `article_raw` не бэкапим, архивная БД по воскресеньям).
- Годовая архивация: `php ops/archiveyear.php ГГГГ` (без `--run` только план; атомарная замена таблиц, id продолжаются, последние 7 дней копируются обратно против дублей).
- Сырой RSS (`article_raw`) хранится 30 дней.
- **Telegram** (тип `telegram`): вводится username публичного канала (`durov`, `@durov` или `t.me/durov`), краулер читает веб-превью `https://t.me/s/<username>` (последние ~20 постов); при первом запуске можно догрузить историю назад по `?before=<id>` (20 / 100 / 500 / 1000 постов). Пост = статья: заголовок: первая строка (до 140 символов), текст целиком, ссылка `t.me/<канал>/<id>`, дата из поста, правки постов отслеживаются. Посты без текста (только фото/видео) пропускаются; ответы-цитаты и пересланное в текст не примешиваются. Работают только публичные каналы с включённым веб-превью; группы и чаты нет. Страницу t.me парсер проверен на копии разметки, на живом t.me проверить при первом подключении.
- **Facebook** (тип `facebook`): прямое чтение невозможно (логин-стена, блокировка серверов), поэтому лента создаётся в rss.app (или аналоге) для публичной страницы/группы, её RSS-адрес вставляется в источник; дальше обрабатывается как обычный RSS. Ссылки facebook.com в поле отклоняются с подсказкой. YouTube не храним.
